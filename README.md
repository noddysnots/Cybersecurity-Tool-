# Triage Console

When a cloud security alert fires, the engineer jumps between the alert, four log types, policy config, and a CLI to answer one question: is this a real threat, a misconfiguration, or noise? Context is scattered, so reaching a confident decision is slow and evidence gets lost between tools. **Triage Console** is a static demo of an alert triage workspace built for **Priya Nair**, an L2 Cloud Security Engineer on a Prisma Access style SASE for about 4,000 users and 12 branch sites. She handles 30 to 50 alerts per shift, starts from time and entities (TAC habit), and needs to close clear cases fast while escalating real threats with evidence already collected.

## Review in 5 minutes

1. Open the live app (or run locally) and pick **Scenario A** from the start screen with Guide on.
2. Follow the coach marks through time scope, logs, console verify, and resolve.
3. Toggle **Annotations** on the alerts, investigate, and resolve screens to see design decisions on the real UI.
4. Optionally finish Scenarios B and C. Read the Brief page in the app for problem, persona, and credits.

## Local setup

Requires Node.js 20+.

```bash
npm install
npm run generate
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Useful scripts: `npm run lint`, `npm test`, `npm run build`.

## Tech stack

Next.js (App Router) and TypeScript (strict), Tailwind CSS, TanStack Table and Virtual, Zustand, cmdk, lucide-react, Motion, Vitest. Static data from `src/data/*.json` (generated by `scripts/generate-data.ts`). No backend. Deploy on Vercel.
